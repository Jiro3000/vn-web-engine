# YU-RIS

The TypeScript runtime reads YPF archives, YBN tables and scripts and executes the YU-RIS task VM. It implements the native variable and expression model, control flow, input, windows, layers, text, sound, file operations, PRODUCT and save buffers. Host interfaces supply platform services; the engine does not choose behavior by game name.

## Native evidence

Addresses in source comments are virtual addresses in `hajiron.exe`, SHA-256 `feb81d5e34bb7ecd784e61f476a0f321a4c4dddb88956f212eac21b55bbba043`. Addresses starting with `100` and explicitly named DLLs refer to those libraries, including YSWBP.DLL's libwebp decoder. EXE and DLL files are static evidence and resource containers; they are never executed or emulated.

YPF registration follows 0x464A3C, including ignoring files without an archive signature and overlaying update archives. YBN readers live in `src/formats/yuris`. VM code lives in `vm`; shared codecs and browser/OS services live outside the engine.

## YBN version 500

Projects whose YBN tables carry version 500 run the behavior of the version 500 build, Relirium.exe SHA-256 `3454f9b48c19443ad4046b22d0188f0dc888cb01089f4ecefd251b40bc06759e`. Comments name its addresses as "Relirium.exe 0x…" and its libraries by name (YSOPS.DLL, YSOGG.DLL, YSWBM.DLL). The VM and most command handlers are the same code at relocated addresses. The version-specific parts are:

- YSCF (0x49333C) has a 16-byte image search order, an 8-byte sound order and settings, thread mode and caption at shifted offsets. System variable 0x6C reads the YBN version (0x478560).
- The resolver (0x46FB20) knows bmp, png, jpg, gif, ydg, webp, jxl, qoi and avif images (order codes 1-9) and wav, ogg and opus sounds (codes 1-3).
- YPF data hashes are xxHash32 with seed 0 (0x44D548), not MurmurHash2; the archive version is 500 in both builds. After a failing hash or inflate, the native tries a 1 KiB-block XOR parity record stored after the entry (0x44D190); intact archives never reach it, and the browser reader neither checks hashes nor repairs entries.
- YDG images (`src/formats/yuris/ydg.ts`, loader 0x4499FC) stack up to 16 strips, each a WebP (libwebp in the EXE) or QOI (`src/formats/qoi.ts`, reference `qoi.h` at 0x44C664) image; JPEG XL strips (YSJXL.DLL) are decoded only when the host supplies a decoder. The browser decodes the strips concurrently on image workers, as the 16 native strip workers (0x44C370) do: the strip pool has one worker per hardware thread except the page's, at most 16. It falls back to in-thread decodes without workers. YDG and QOI loads always set the masked-blitter flag; PNG loads also set it for a tRNS chunk (spng_get_trns, 0x44B1BC).
- Opus sounds use YSOPS.DLL (opusfile): codec byte 2, 48 kHz 16-bit, length trunc(op_pcm_total · 1000 / 48000) ms, and `op_read` is passed the frame count as its sample count, so a read near END takes at most n / (2 · channels²) frames and an empty read ends the play. Ogg Vorbis moved to YSOGG.DLL with the old behavior.
- MATH RND draws from xoshiro128++ (0x476424), seeded at start-up (0x499024, 0x49D0FC) through a MurmurHash3-finalizer split of one 32-bit seed (0x492634).
- PRODUCT (0x488B00) drops COM 10, 0x21, 0x24 and 0x25, sets LET to 0 for COM 3, ignores COM 0x3E9/0x3EA without YSOHC.dll and adds the YSWBM.DLL WebM COMs. MOVIEEND (0x47A8D8) also paints a black 1280x720 rectangle on the main window (0x47A930).
- YSWBM.DLL (`vm/yswbm.ts`; nestegg, libvpx 1.15.2, libyuv) backs PRODUCT COM 0x5DC1 (ordinal 1: `fopen` of PSTR in the game folder, first video track, VP8 or VP9 only; any failure returns -1 and shows `YSWEBM_PRELOAD Error. ret = -1`), 0x5DC2 (ordinal 2: the next shown frame into the buffer of the layer PSTR names, rows `width · 4` bytes apart; LET receives 0, 1 at the end of the stream, -1 without a stream; the layer's area is then marked), 0x5DC3/0x5DC4 (ordinals 3 and 4: last packet time and segment duration in ms into 0x893740/0x893748) and 0x5DC9 (ordinal 5: close). The scenario library decodes up to 16 frames per call to catch up with the playing sound's TIME at 30 frames per second. The shared `src/video/webm-video.ts` demuxes with `src/formats/webm.ts`, decodes through WebCodecs and converts with libyuv's BT.601 constants (`src/video/libyuv.ts`).
- WINDOW (0x485750) remembers each window's last Z (bytes 0x5CB0DC, initially -1) and calls SetWindowPos only when Z changes.
- Scripts load on first use (0x480769). A script listed in `yst_list.ybn` but missing from the archives only fails when a task reaches it.

Divergences of the version 500 path:

- Opus decoding uses libopus through WebCodecs `AudioDecoder` (mono and stereo streams with channel mapping family 0 and no output gain) or else the browser's `decodeAudioData` at 48 kHz, instead of opusfile. The PCM range and every timing use opusfile's granule arithmetic (`readOggOpus`: pre-skip and final-granule trim), but sample values can differ (no opusfile dither; `decodeAudioData` is not libopus). Without a browser decoder (Node), Opus sounds play silence of the native length.
- The xoshiro128++ seed uses only the host time; the browser has no thread or process ids or performance-counter words to mix in.
- JPEG XL and AVIF standalone images use the browser's image codecs where available; this build's JPEG XL strips inside YDG have no decoder and leave their rows empty.
- WebM frames come from the browser's WebCodecs `VideoDecoder` instead of libvpx; the YUV to BGRA conversion is libyuv's fixed-point arithmetic. Chunks are fed a few packets ahead of the reader. Without a decoder (Node), each shown frame counts with the layer's pixels left as they are. A PSTR naming no layer reads as a null buffer (-2) instead of the native null dereference, and writes stop at the end of the layer's buffer.

## Verification

After `npm run build:runtime`, run `node tools/verify-yuris.mjs /path/to/installation` to check archive name/data hashes, inflation and all script tables. Add `--webp` to decode every archived WebP and print a combined BGRA hash, `--ydg` to decode every YDG image (failing on any strip that does not decode) and `--opus` to check every Ogg Opus file's head, link count and length. The data hash algorithm follows the project's YBN version. `node tools/verify-webp.mjs` requires `cwebp` and `dwebp` on PATH and compares synthetic lossless/lossy/alpha fixtures byte for byte. `tests/webp.test.mjs` checks small synthetic fixtures without external binaries. No verification needs to display game images.

The shared WebP decoder emits straight BGRA and supports VP8L, VP8 and VP8X with ALPH. Its default color conversion matches modern libwebp, whose intermediate fixed-point products round differently from libwebp 0.4. YU-RIS hosts must pass `true` as `decodeWebp`'s second argument to select the native 14-bit scalar conversion (YSWBP.DLL 0x10021090 and related upsamplers). Animated WebP is rejected.

YMV (0x45886C) is a YSMV container of independently indexed, XOR-obfuscated color and grayscale alpha JPEG pairs. The movie belongs to the shared CG object and is released by YMVEND or its final layer reference. YMVINFO reads the container metadata; FRAME clamps to the first/last frame. DIALOG (0x43CD48) uses shared modal message/input services. Its FILEOPEN branch and the additional checkbox/slider arguments are unused in this executable.

CGACT TEXT (0x427D0F) consumes FONT's monochrome glyph DIB and measured advance (0x442390). Its native CPU rasterizers (0x4298D0/0x42B444) support 4x4 coverage, straight-alpha blending, mono replacement, all gradient/rotation modes and SET's offset passes. The text operation continues to later CGACT tests; it does not consume a following COPY or MERGE operation.

MOVIE/MOVIEEND/MOVIEINFO (0x44A010/0x44A5FC/0x44A650) use physical folder files and OS media services, separately from YMV. The fixed native backend is DirectShow (0x59B790 = 1); its 4000·log10 volume conversion is preserved. PLAY=1 returns once the media is opened (VMR9PlayMovie builds the graph, then IMediaControl::Run returns without waiting for the first frame); a failure to open shows 0x18C86 and a later playback failure ends the movie. Tasks continue during playback, while window composition/output pauses unless PRODUCT COM 0x1B enables it.

MENU/MENUACT/MENUEND/MENUINFO (0x448F74..0x449570) maintain a separate M0 tree.
Menu installation takes a snapshot in Z order: E hides entries, A disables them,
CHECK marks them, empty NAME creates a separator, and groups with children create submenus.
WM_COMMAND exposes the selected CODE's low word through system variable 0x84.
Popup menus remain inside the browser viewport and outside the owner's clipping.
Virtual hide/show preserves a minimized window's iconic state; restoration delivers
activation before the VM's foreground suspension check (0x45D738 / 0x41022A).
WINDOW MENUID installs a window menu; TRAY (0x452FB4) retains its label, optional
16x16 BGRA icon and independently installed menu snapshot.

## Host differences

- The bilingual scenario library can receive `VO2`, `VO3` and `VO4` cues embedded at the start of the quoted Japanese `ML.TEXT` argument. Scenario loading moves these cues before `ML.TEXT` so the regular voice macros handle them in either language. The archived bytes and source line numbers stay intact.
- Menus and the tray use page controls instead of OS chrome. The default application tray icon is represented by its label. Menu labels have dynamic storage rather than the native 0x105-byte allocation.
- PRODUCT caption uses a dynamically sized string rather than a fixed native buffer.
- GBK messages cross the host boundary already decoded.
- LOAD integer/float writes clamp to the allocated destination.
- Snappy and zlib output is compatible but does not reproduce native compressed bytes. A variable record whose uncompressed bytes match the previous record of that variable reuses its stored bytes instead of compressing again.
- Serialized layer structs contain zeros except for the sizes.
- Memory snapshots omit a native zlib allocation bound. Unchanged memory slots reuse their previously compressed bytes, and the remaining slots compress concurrently.
- Host write failures propagate instead of raising native error 0x18EFC.
- LOAD without FILE or MEM uses an empty filename.
- The TEXT line buffer is not bounded to 0x1000 bytes.
- CGACT TEXT bounds DIB and destination accesses to their allocated storage; invalid glyph sizes that divide by zero in the native rasterizer raise RangeError.
- MATH3D uses JavaScript double precision instead of x87 80-bit intermediates.
- GRADATION retains the native full-source stride for a cropped destination, but discards writes outside the allocated buffer instead of corrupting memory. Vertical ramps also discard rows outside the source height.
- ROTATION discards accesses outside allocated pixel storage. Fresh output buffers start at zero instead of exposing native malloc contents in regions its worker leaves unwritten. Its trigonometric intermediates use JavaScript doubles instead of x87 extended precision.
- A key or mouse-button press ends the frame pacing `Sleep` of 0x4109A8 early: that frame is shown at once and the next pass, which polls the press, starts without waiting out the frame. Its pacer then takes the late-frame path and restarts the frame grid at that moment. Natively the press waits for the sleep to end.
- YMV frame JPEGs are decrypted into owned copies rather than mutating the archive buffer.
- The browser host inflates archived YMV files progressively instead of reading them whole (0x45886C). YMV returns once the header and frame table have arrived, and each FRAME waits for its JPEG pair. A read or inflation failure raises the open error 0x1964A at the first FRAME that needs the missing bytes.
- YMV can decode color and alpha JPEG pairs in browser workers and prepares a bounded window of upcoming frames. JPEG decoding uses the browser codec instead of the native libjpeg build; numeric readback can differ, including one-level channel differences in grayscale alpha JPEGs.
- Hot script ranges are compiled to JavaScript (`vm/region-compiler.ts`). After an IF/ELSE/IFBLEND/IFEND/INT/FLT/STR/LET, LOOP-family or GOSUB/RETURN instruction has run 16 times, the machine compiles the following run of such instructions whose handlers are native, whose decoder argument checks cannot fail and that no trace observes. LOOP compiles for counts from 1 to 15 (except the five-instruction character search); the other counts, and LOOPEND for loops an interpreter scan skips through, stay with the interpreter batches. GOSUB compiles for a constant label in a loaded script and then applies the interpreter's folds of recognized STR/INT library entries; RETURN compiles inside a call, and both continue in the target script. Expressions support int, float and string literals, script variables (scalar and in-bounds elements), the state-only int, string and float system variables (frame parameters and results, the loop counter, task values, pi and fixed environment values) and the integer, float and string operators in the evaluator mode of each argument type; float modes keep doubles outside array indexes, and int modes round float values by FISTP. Anything else ends the range. Variable types and element bounds are guarded at run time: a failing guard returns to the interpreter at that instruction before it changes state. The evaluator's scratch state (`lastIndex`, the last variable id and its buffers) is not updated by compiled ranges; only reads of untyped variables observe it, and those are not compiled.
- The browser MOVIE host uses its installed media codecs and a child video element in the virtual window, rather than DirectShow filters or MCI. Codec availability, color conversion and scheduling follow the browser.

## Browser player

`yuris.html` opens a read-only folder selection and applies `updateN.ypf` after `pac/`. Browser saves use an IndexedDB overlay keyed by archive-index identity; the installed files are never written. The working folder (`src/platform/legacy-folder.ts`) knows every file it can hold, so reads of archived assets skip the overlay, and files the game writes read back from the folder's copy without a store snapshot. `YurisBrowserPlayer` binds the VM to shared page windows, monochrome font rasterization, codecs, folder storage, registry, dialogs and mutable PCM output. Pointer coordinates are scaled from the displayed canvas to game pixels (0x403F2C).

The browser can compose the main window with integer WebGL2 textures for supported flat mode-0 layers, rule transitions, SIZE2 scaling and unruled additive layers. Script pixel access materializes the native BGRA window on demand. Unsupported layer trees and unavailable hardware rendering use the software compositor. The WebGL queue is bounded at two frames; when a long script task fills it, the player blocks on the queued GPU work instead of recomposing on the CPU. Both paths present an opaque BGRX window through Canvas 2D, matching the native GDI copy (0x45ECF4). PNG and WebP loaders retain the native alpha-blitter flag for layer composition.

CGCASH (0x43E0C8, loader 0x417DDC) queues PNG and WebP decodes on shared browser workers. Its prepared cache has a 160 MiB budget, partitioned into 56 MiB for WebP, 68 MiB for PNG files with at least 2 MiB of encoded data, and 36 MiB for smaller PNG files. Foreground decodes go to a separate 96 MiB least-recently-used cache; a decode requested a second time moves to a 64 MiB reuse cache that single-use decodes cannot evict. Uniform decoded buffers are stored as a single packed pixel in a list of 256 entries outside both byte budgets. Each layer receives mutable pixels of its own, and the loader verifies the encoded bytes before reusing a decode. After the standard scenario parser has waited for a click for 60 ms, the browser prioritizes PNG, YDG and QOI hints through the next dialogue in the same prepared-cache budget. Library revisions number the scenario library's variables differently, so the lookahead locates each one in the routine that uses it (es.SCENARIO.PARSER, es.CASH.ADD.MAIN, es.TRDEF, es.SP.CHK.SPLZ, es.SP.RELOAD, es.L.YMV.INIT); the numbers below are those of the revision the YSTB addresses cite. It reads the library’s forecast, literal multilingual and portrait paths, and the last observed sprite resolution. The same scan reads the YMV files that S.MV opens (es.L.YMV.INIT: V$5491[6], the sprite name and `.ymv`) into a bounded progressive read-ahead that the YMV loader claims while it is still inflating. A dialogue is an `ML.TEXT` macro or a TEXT token of es.SCENARIO.LEXER (a plain text line). Choices, conditional jumps and unknown macros stop the scan: an es.ScenarioMacro routine runs in line when the routines it calls with constant labels never write the parser cursor (es.Scenario.JumpLabel) and never reach the choice routines ES.SEL and ES.SEL.GO; until that analysis has read the library, a fixed list of standard macros applies. A `#` label line runs no command (es.SCENARIO.PARSER, YSTB59:163–192) and does not stop the scan. Block comments are skipped as es.SCENARIO.LEXER skips them: `/*` at a token start sets the comment flag H@2909 (YSTB57:96–98), which carries over to later lines until a `*/` (state 99, YSTB57:264–271). A scan reads at most 256 lines ahead. The same library analysis follows each macro's arguments through es.ScenarioMacro.SetParam (YSTB62:5–14) and the GOSUB parameters V$55[k] of the routines it calls, three levels deep. Requests that every call makes, outside IF and LOOP blocks, become hints: es.SP.CG.SET with a literal kind loads the kind folder V$5534[kind] and the name argument (YSTB180:0, 156:215), and es.SP.TR.SET loads a transition rule from the folder es.SP.LOADTR names (YSTB160:135–149). A macro that always reaches es.Scenario.JumpLabel continues the scan at the label it names: the first entry of that name in the parser's label table (es.Scenario.SearchLABEL, YSTB59:72) gives the line and file number, and es.SCENARIO.FILENAME.GET the file. Another file is read once through the TEXT line split of es.SCENARIO.LOAD into a cache of eight files, and the scan resumes on the next update. The library's own forecast list covers the current file only, so it is not used after a jump. Speculative decodes use a background lane of the shared decode workers: their jobs start only on an idle worker, so a decode the frame waits for never queues behind them. Foreground PNG loads also decode on a worker; the whole-image pool keeps one worker more than speculative decodes may occupy. The images of the next click have two preload slots beside the two CGCASH slots, and their worker jobs start before other speculative jobs. A foreground load of an image that is still warming promotes that decode's remaining jobs and uses its result instead of decoding the file again. When the VM reads the first stand image of a pass at a scale folder, the browser starts worker decodes for the images the same pass loads next: the slots whose draw size (V@5318) es.SP.CHK.SPLZ moves to another folder band, read from that routine's own bands, and the T/FACE sprites of the scenario lines before the next dialogue at the folder just read. The foreground loader then waits for those decodes instead of decoding each file in turn. A CG FILE load inside a LOOP (es.ZENKAKU.LOAD loads every page of an atlas this way) also starts the loads of the next eight iterations: the VM evaluates the FILE expression with the loop counter H@48 advanced, then restores the counter and the last-variable record.

Large software blends of every MODE and SIZE2 can use WebAssembly SIMD or table kernels with the native scalar integer rounding; blends into a resident compositor buffer use them from 1024 pixels. The compositor can evaluate an unchanged source layer's pending SIZE2 transform for only the damaged rectangle. Script pixel reads still resolve the full image. When the source layer is about to change, a pending transform keeps the buffer it captured: a replaced or released buffer as it is, a buffer written in place as a copy. It is evaluated only when its result is read, with the pixels the native CGACT would have scaled at once. The copy takes over the source pixels the SIZE2 kernel staged in linear memory, and once a source is staged, clipped SIZE2 draws use the kernel from 1024 pixels. TRANSITION keeps both whole inputs staged between calls, keyed by buffer and pixel revision, so a fade over unchanged layers stages each input once. SIZE5 runs both Lanczos passes in a WebAssembly kernel when every tap stays inside its line; the 32-bit wrapping sums and truncating division are those of the scalar passes. Node lookups cache the component split of each path string. The VM can batch validated in-bounds array initialization and forward shifts and skip empty iterations of array guards, including guarded IF/ELSE chains. It recognizes bytecode for the library's CP932 substring, character search, lexer loops and two-range lookups. These paths keep the VM's scratch variables and replay the last skipped iteration where necessary. Instruction tracing uses the interpreter for any range the observer reads.

Game options connects the virtual main window to the shared fullscreen controls. True fullscreen uses browser user activation. Native fullscreen can fall back to a page-filling view until a player clicks Enter fullscreen.

DOM text uses the shared selectable glyph presentation for the standard atlas library. Its hook positions and variables are read from the authored YBN code of `es.ZENKAKU.LOAD`, `es.ZENKAKU.DRAW.ONE`, `es.SJISCODE.DRAW.ONE` and `es.TX.OUTPUT.ONE` (the final CGACT MERGE, the GOSUB arguments PINT5/6/9, VARINFO SJISCODE, the `CGFTX.` layer name and the `V@n[36,k]` settings row), because library revisions renumber and resize these routines. Glyph provenance follows CGACT merges and copies into the display. The Sarasa Gothic SC atlas family carries GBK bytes through the same library; other atlas names are CP932, and Gothic atlases present in a Japanese sans face. The native BGRA buffers remain available to saves and readbacks, while the DOM view presents a separate textless plane. Browser font shape and the effects of the native atlas passes are approximate. Image-only glyphs and independent CGACT TEXT rasterizers remain in the bitmap. Sound buffers use the shared mutable PCM processor in an AudioWorklet (or the shared ScriptProcessor compatibility host). Commands are posted in order without waiting for each acknowledgement, because the processor port keeps message order; the browser frame boundary waits for one status reply per buffer, which follows every earlier command, and reads the actual audio render cursor; synchronous VM cursor reads use that last acknowledgement. This can lag within a frame, unlike the native sound thread. Pitch changes alter sample consumption in the render processor.

Ogg sounds open from the worker's Vorbis headers and begin playback once the first required half-buffer is ready. The worker decodes the remaining PCM in order. Opus sounds open from the granule length the same way while `AudioDecoder` fills their PCM in order; the whole-file `decodeAudioData` fallback holds the first fill until it finishes. Each fill waits for the samples it reads, including when a script seeks ahead (0x41CCDC, 0x41DEC0). While the standard scenario parser waits for a click, the player reads and starts decoding the `VO` cues (Vorbis or Opus) of the lines up to the next dialogue. It derives each path from the first voice file the script opened. A later open of the same bytes takes over that decode; an unclaimed decode is discarded after four newer ones.

Atlas dialogue from `es.TX.OUTPUT.ONE` supplies the configured full-width advance to DOM text. Browser tracking stays fixed as glyphs are revealed, with punctuation shaped by the browser font.

Browser windows live on a virtual desktop; fullscreen, activation, screen wake locks and process operations use the shared browser platform policy. Local Windows executables are never launched. The font provider offers CSS family aliases and uses browser fallback fonts where a native family is unavailable; glyphs therefore need not match Windows GDI. SimHei text uses GBK and the Japanese aliases use CP932. Browser image encoders may produce different compressed output and alpha rounding from native encoders. Invalid ONMOUSE window zero is mapped to the main window rather than reading before the native window pointer array.
